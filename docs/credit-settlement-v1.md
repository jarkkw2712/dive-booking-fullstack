# รับชำระยอดเชื่อ รุ่น 1

รายการรับชำระเก็บแยกจากยอดขายเชื่อเดิม และบันทึกพร้อม Booking ใน transaction เดียว มีรหัสป้องกันการบันทึกซ้ำ ตรวจสิทธิ์และยอดรวมไม่ให้เกินยอดเชื่อ และเก็บผู้บันทึกไว้ใน audit log ประวัติที่บันทึกแล้วไม่มีปุ่มลบหรือแก้ไขในรุ่นนี้

รายงานที่เปลี่ยนมีเฉพาะใบสรุปยอดใบสำคัญรับเงิน: แถวเดิมในวันเดินทางยังเหมือนเดิม รายการที่ชำระในวันอื่นเพิ่มเป็นแถวสีแดงในวันที่ชำระ สำหรับรายการที่ชำระวันเดียวกับวันเดินทางไม่เพิ่มแถว แม้เก็บประวัติการชำระไว้ รายงานอื่นและ Financial ไม่ดึงรายการใหม่นี้ จึงไม่ควรตีความว่าเป็นการลงรับเงินใน Financial อัตโนมัติ

## ก่อนใช้งานจริง

1. สำรองฐานข้อมูลและยืนยันว่ามี migration เดิมถึง `20261030_050_island_addon_days.sql` แล้ว
2. รัน `supabase/migrations/20261107145557_credit_settlement_v1.sql` ด้วยสิทธิ์ที่เหมาะสม ตรวจผลให้สำเร็จ
3. Deploy backend แล้วจึง deploy frontend ที่ตรงกัน จากนั้นทดสอบด้วยข้อมูลทดสอบที่ได้รับอนุญาต ทั้งแบ่งชำระ วันเดียวกัน สิทธิ์ผู้ใช้ และรายงาน

ห้าม deploy backend ใหม่นี้ก่อน migration เพราะรายงานใบสรุปยอดใบสำคัญรับเงินต้องอ่านตารางใหม่ ไม่ต้องแก้ข้อมูล Booking เก่า และไม่ต้องเปิด service-role key ให้ frontend

## การย้อนกลับ

ห้ามลบตารางหรือข้อมูลรับชำระเพื่อย้อนระบบ หากจำเป็นให้เก็บและสำรองประวัติทั้งหมดก่อน และระงับการแก้ยอดเชื่อของ Booking ที่มีรายการรับชำระระหว่างใช้ backend รุ่นเก่า เพราะรุ่นเก่าไม่ตรวจยอดรับชำระใหม่นี้ รายงานรุ่นเก่าจะไม่แสดงการชำระที่เพิ่มเข้ามา จึงต้องกระทบยอดก่อนกลับมาใช้งานและทดสอบแผนย้อนกลับในระบบทดสอบก่อนเสมอ
